# Topic4 — Коллекции (Array, List, Dictionary и прочие) — Теория и примеры

Цель: дать теоретическое и практическое понимание основных коллекций .NET, их сложности по операциям и сценариях использования в автотестах.

Ключевые структуры
- `Array` — фиксированная длина, быстрый доступ по индексу, нет методов `Add`/`Remove`.
- `List<T>` — динамический массив, быстрый индексированный доступ, добавление/удаление O(1) амортизированно/ O(n) для удаления по индексу.
- `Dictionary<TKey,TValue>` — хэш-таблица, быстрый доступ по ключу O(1) амортизированно.
- `HashSet<T>` — набор уникальных значений, эффективная проверка наличия.
- `Queue<T>` / `Stack<T>` — FIFO / LIFO для обработки задач/операций.
- `SortedList<TKey,TValue>` / `SortedDictionary<TKey,TValue>` — словари, поддерживающие упорядоченный список ключей.

Лекционный материал
1. Когда использовать `List<T>` vs `Dictionary<TKey,TValue>`
- Используйте `List<T>` для упорядоченных наборов, когда важен индекс и порядок элементов.
- Используйте `Dictionary` когда основной сценарий — быстрый поиск по ключу (например, конфиг по имени настройки).

2. Сложности по операциям (Big O)
- Доступ по индексу в `List`/`Array` — O(1).
- Поиск в `List` (без индекса) — O(n).
- Поиск по ключу в `Dictionary` — O(1) амортизированно.
- Добавление в `HashSet` — O(1), дубли не добавляются.

3. Best practices для QA
- Для конфигов тестов используйте `Dictionary<string,string>`.
- Для набора уникальных элементов (например, найденных элементов страницы) используйте `HashSet<string>`.
- Возвращайте `IEnumerable<T>` или `IReadOnlyList<T>` из публичных API, чтобы не позволять внешнему коду изменять внутреннее состояние коллекции.

4. Примеры кода и сценарии
- Пример: подсчитать, сколько раз на странице встретился текст с помощью LINQ `.GroupBy(x => x.Text).Select(g => new { g.Key, Count = g.Count() })`.
- Пример: очередь задач для обработки ответов бэкенда — `Queue<WorkItem>`.
