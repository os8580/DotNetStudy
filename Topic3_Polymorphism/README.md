# Topic3 — Наследование и полиморфизм (Лекция и практические примеры)

Цель: понять механизмы наследования, виртуальных методов, абстракции и полиморфизма — и как эти принципы применяются при проектировании Page Objects и тестовой логики.

Ключевые понятия
- Наследование — способ создания нового класса на базе существующего (`class Derived : Base`). Позволяет переиспользовать код и расширять поведение.
- Виртуальные методы (`virtual`) и переопределение (`override`) — дают возможность подклассу изменить реализацию базовой логики.
- Абстрактные классы и методы (`abstract`) — определяют контракт и обязательную реализацию в потомках.
- Полиморфизм — способность работать с объектами через ссылку на базовый тип или интерфейс, вызывая конкретную реализацию в runtime.

Лекционный материал
1. Зачем нужен полиморфизм
- Позволяет писать код, не зависящий от конкретных реализаций: тесты работают с `IBrowser`/`IPage` вместо `Chrome`/`Firefox`.
- Упрощает расширение системы: добавление нового браузера не требует изменения кода, использующего абстракцию.

2. Виртуальные методы и шаблонный метод
- Шаблонный метод: в базовом классе описывается алгоритм, а отдельные шаги делегируются виртуальным методам, которые можно переопределить в потомках.
- Это полезно для Page Objects — общий сценарий навигации с различной реализацией для каждой страницы.

3. Абстракция vs Интерфейсы
- Абстрактный класс может содержать состояние и частичную реализацию; интерфейс только контракт.
- Если нужна общая логика и состояние, используйте абстрактный класс; если только сигнатуры — интерфейс.

4. Коэффициент сложности и поддерживаемость
- Избегайте глубоких иерархий (больше 3-4 уровней) — это затрудняет понимание.
- Предпочитайте композицию (вложенные объекты) наследованию, когда это применимо.

QA-ориентированные примеры
- `Browser` (абстрактный) с методами `Launch()`, `Navigate(string url)`, `Close()`; `ChromeBrowser` и `FirefoxBrowser` реализуют детали запуска и взаимодействия.
- `Page` как базовый класс для Page Objects, содержащий ссылку на `IBrowser` и общие утилиты (`Find`, `Click`, `Wait`).
- Тесты могут принимать `Page` или `IPage` и работать с любым браузером/реализацией.

Практические задания
- Реализовать `Browser` как абстрактный класс и два наследника `ChromeBrowser`/`FirefoxBrowser`. В `Program.cs` создать `List<Browser>` и вызвать одинаковые методы — показать полиморфизм.
- Создать `BasePage` с виртуальным методом `Open()` и переопределить его в `HomePage`/`LoginPage`.
- Перепроектировать один из Page Object-ов, заменив наследование композицией, и оценить преимущества.

Антипаттерны
- «God object» — класс, который делает слишком много; разделите обязанности.
- Сильная связь с конкретными реализациями (жёсткие зависимости) — затрудняет тестирование и подмену.

Рекомендации
- Дизайн тестовой архитектуры: интерфейсы для внешних сервисов, абстрактные классы для общей логики страниц, конкретные реализации для реальных драйверов.
- Покрывайте сложные решения комментариями и диаграммами (если проект большой).
