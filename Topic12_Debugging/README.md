## 1. Что такое отладка и зачем она нужна?

### Аналогия

```
Без отладки (полет вслепую):
"Программа упала. Почему? Не знаю. Может быть, ошибка в строке 42?"
"А может в строке 100? Давай добавим Console.WriteLine везде!"

С отладкой (управляемое расследование):
"Программа упала. Поставлю точку останова ДО ошибки.
Пошагово выполню код. Смотрю, какое значение неправильное.
Нашел! Вот здесь переменная x = 0 вместо 10. Отсюда ошибка!"
```

### Отладка (Debugging) — это:

- **Поиск ошибок (bugs)** в коде через инструменты
- **Пошаговое выполнение** кода с остановками
- **Инспекция переменных** в конкретный момент
- **Понимание потока выполнения** программы

### Зачем нужна в QA:

- Понять, почему тест упал (что происходит в коде?)
- Проверить, передается ли правильное значение в метод
- Найти, где именно происходит ошибка (не гадать, а знать!)
- Изучить, как работает чужой код

## 2. Точки останова (Breakpoints)

### Что такое breakpoint?

Точка, в которой программа **останавливается**, чтобы вы могли посмотреть состояние переменных.

### Как установить в VS Code:

1. **Нажмите на край строки** (слева от номера) — появится красная точка
2. **Или нажмите F9** на выбранной строке
3. **Или щелкните правой кнопкой** → "Add Breakpoint"

```csharp
public class Calculator
{
    public int Add(int a, int b)
    {
        int result = a + b;  // Точка останова здесь (нажмите F9)
        return result;
    }
}
```

### Типы breakpoints:

| Тип                 | Как создать           | Зачем                             |
| ------------------- | --------------------- | --------------------------------- |
| **Line Breakpoint** | Нажать на край строки | Остановиться на конкретной строке |
| **Conditional**     | Правый клик → условие | Остановиться, если условие верно  |
| **Hit Count**       | Правый клик → счет    | Остановиться после N попаданий    |
| **Logpoint**        | Правый клик → лог     | Вывести в консоль без остановки   |

### Практический пример:

```csharp
// Найти баг: почему тест не проходит?
public class LoginTest
{
    [Test]
    public void TestLoginWithWrongPassword()
    {
        var page = new LoginPage();
        page.Username = "alice";
        page.Password = "wrong";      // ← Breakpoint здесь (F9)
        bool result = page.Login();
        Assert.IsFalse(result);       // ← И здесь
    }
}
```

Когда нажмете F5 (Debug), программа остановится на первой точке и вы сможете проверить значение `page.Password`.

## 3. Пошаговое выполнение (Stepping)

### Step Over (F10)

**Выполнить текущую строку целиком**, не заходя внутрь методов.

```csharp
int result = Calculator.Add(5, 3);  // F10 → метод Add выполнится целиком
                                    // result = 8, переходим на следующую строку
```

**Когда использовать:** когда вы доверяете методу и хотите пропустить его внутренность.

### Step Into (F11)

**Зайти ВНУТРЬ метода** и смотреть пошагово, что там происходит.

```csharp
int result = Calculator.Add(5, 3);  // F11 → входим внутрь Add()
                                    // Смотрим: a = 5, b = 3
                                    // result = a + b = 8
                                    // return result
```

**Когда использовать:** когда подозреваете ошибку ВНУТРИ метода.

### Step Out (Shift+F11)

**Выйти из текущего метода** и вернуться в вызывающий код.

**Когда использовать:** вы зашли в метод, но поняли, что здесь не ошибка. Выходите и ищете дальше.

### Сравнение:

| Операция      | Клавиша   | Что происходит                           |
| ------------- | --------- | ---------------------------------------- |
| **Continue**  | F5        | Продолжить выполнение до следующей точки |
| **Step Over** | F10       | Выполнить строку, не заходя внутрь       |
| **Step Into** | F11       | Зайти внутрь метода                      |
| **Step Out**  | Shift+F11 | Выйти из текущего метода                 |

## 4. Инспекция переменных (Variables и Watch)

### Встроенное окно Variables

При остановке на breakpoint видны ВСЕ переменные текущей области:

```csharp
public void TestUserCreation()
{
    string name = "Alice";
    int age = 30;
    bool isActive = true;
    // ← Breakpoint (F9)
}
```

**В окне Variables вы увидите:**

```
name: "Alice"
age: 30
isActive: true
```

### Окно Watch

**Добавьте выражение**, которое вам интересно отслеживать:

1. Нажмите **Debug → Add to Watch** или
2. Правый клик на переменной → **Add to Watch**

```csharp
// Например, отслеживаем изменение age:
age = 25;    // Watch: age = 25
age += 5;    // Watch: age = 30
age--;       // Watch: age = 29
```

### Практический пример для QA:

```csharp
// Тест падает. Какое значение неправильное?
[Test]
public void TestElementSelection()
{
    var elements = driver.FindElements(By.Class("button"));
    // ← Breakpoint: сколько элементов найдено?

    Assert.AreEqual(5, elements.Count);  // Ожидаем 5, а найдено сколько?
}
```

Вы сразу видите в Watch:

- `elements.Count = 3` ← Вот проблема! Элементов только 3, а не 5!

## 5. Отладка в VS Code (launch.json)

### Создаем конфигурацию отладки:

1. **Откройте Command Palette** (Ctrl+Shift+P)
2. **Введите:** Debug: Add Configuration
3. **Выберите:** C# (.NET)
4. **Создается файл** `.vscode/launch.json`

### Основная конфигурация:

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": ".NET Core Launch (console)",
      "type": "coreclr",
      "request": "launch",
      "preLaunchTask": "build",
      "program": "${workspaceFolder}/Topic12_Debugging/bin/Debug/net6.0/Topic12_Debugging.dll",
      "args": [],
      "cwd": "${workspaceFolder}/Topic12_Debugging",
      "stopAtEntry": false,
      "console": "integratedTerminal"
    }
  ]
}
```

### Как запустить Debug:

1. **F5** или **Debug → Start Debugging**
2. Программа запускается с отладкой
3. Программа останавливается на breakpoints
4. Вы смотрите Variables, Watch, Stack

## 6. Условные точки останова (Conditional Breakpoints)

### Когда использовать:

Если в цикле 1000 итераций, а ошибка в 500-й итерации, вы не хотите 500 раз нажимать F5!

### Как создать:

1. **Правый клик на breakpoint** → **Edit Breakpoint**
2. **Введите условие:**

```csharp
// Пример 1: остановиться, если i > 500
i > 500

// Пример 2: остановиться, если элемент скрыт
!element.Displayed

// Пример 3: остановиться, если пользователь не найден
user == null
```

### Практический пример для QA:

```csharp
List<WebElement> buttons = driver.FindElements(By.Tag("button"));

for (int i = 0; i < buttons.Count; i++)
{
    var button = buttons[i];
    // ← Conditional Breakpoint: i == 5
    // Остановиться только на 6-й кнопке!

    if (!button.Displayed)
    {
        Console.WriteLine($"Button {i} is hidden!");
    }
}
```

## 7. Логовые точки (Logpoints)

### Что это?

Breakpoint, который **вместо остановки** выводит сообщение в консоль.

### Когда использовать:

- Когда не хочется останавливать программу (отладка "в фоне")
- Когда нужно отследить значения в цикле без 1000 остановок

### Как создать:

1. **Правый клик на breakpoint** → **Edit Breakpoint**
2. **Выберите Logpoint** (не Break)
3. **Введите сообщение:**

```
Итерация {i}, элемент: {element.Text}
```

### Результат в консоли:

```
Итерация 0, элемент: Login Button
Итерация 1, элемент: Submit Button
Итерация 2, элемент: Cancel Button
...
```

## 8. Stack Trace (Стек вызовов)

### Что такое Stack?

Список всех методов, которые привели к текущей точке.

```
Program.Main()
├─ TestLogin()
│  ├─ LoginPage.Login()
│  │  ├─ ValidationService.Validate()
│  │  │  └─ ← Breakpoint ВОТ ЗДЕСЬ (ошибка в строке 42)
```

### Как использовать:

1. **Во время отладки** откройте окно **Debug → Call Stack**
2. **Нажмите на любой уровень**, чтобы перейти туда
3. **Посмотрите значения переменных на каждом уровне**

### Практический пример:

```csharp
// Тест упал в методе Validate()
// Но почему? Какие значения передали?

[Test]
public void TestValidation()
{
    var validator = new ValidationService();
    var result = validator.Validate("invalid@");
    // Когда произойдет ошибка, откройте Call Stack:
    // - Увидите: TestValidation() → Validate() → ValidateEmail()
    // - Можете посмотреть значения параметров на каждом уровне!
}
```

## 9. Практические сценарии отладки

### Сценарий 1: Тест падает, не понимаете почему

```csharp
[Test]
public void TestUserLogin()
{
    var page = new LoginPage();
    // Поставьте breakpoint ДО каждого вызова
    page.Username = "alice";   // ← F9
    page.Password = "pass123"; // ← F9
    bool result = page.Login(); // ← F9

    Assert.IsTrue(result);     // ← Падает здесь
}
```

**Действие:**

1. F5 — Debug
2. Смотрите Variables → какое значение неправильно?
3. F10 — пошагово
4. Нашли? Исправьте!

### Сценарий 2: Ошибка в цикле, но в какой итерации?

```csharp
for (int i = 0; i < elements.Count; i++)
{
    var element = elements[i];
    // ← Conditional Breakpoint: elements[i].Text == ""

    Click(element);
}
```

### Сценарий 3: Метод возвращает неправильное значение

```csharp
public int CalculateTotal(List<Item> items)
{
    int total = 0;
    foreach (var item in items)
    {
        // ← Breakpoint: смотрите, как меняется total
        total += item.Price;
    }
    return total;
}
```

**Watch выражение:** `total` — следите, как меняется значение в каждой итерации!

## 10. Частые ошибки новичков

### ❌ Ошибка 1: Забыли нажать F5 (Debug)

```
"Я поставил breakpoint, но программа не останавливается!"
Решение: Нажмите F5, а не F6 (Run без отладки).
```

### ❌ Ошибка 2: Условный breakpoint никогда не срабатывает

```csharp
// ❌ Неправильно
for (int i = 0; i < 10; i++)
{
    // Breakpoint с условием: i == 100
    // Никогда не будет 100!
}

// ✅ Правильно
// Breakpoint с условием: i == 5
for (int i = 0; i < 10; i++)
{
    // Остановится на i = 5
}
```

### ❌ Ошибка 3: Отладка неоптимизированного кода

```
Release vs Debug конфигурация:
- Debug: медленнее, но полная информация
- Release: быстрее, но меньше информации для отладки

Всегда отлаживайте в Debug конфигурации!
```

## 11. Лучшие практики

✅ **DO:**

- Используйте breakpoints вместо Console.WriteLine для понимания потока
- Отлаживайте пошагово (Step Into, Step Over)
- Смотрите Stack Trace для понимания иерархии вызовов
- Используйте Conditional Breakpoints для больших циклов
- Сохраняйте конфигурацию отладки в проекте

❌ **DON'T:**

- Не оставляйте breakpoints в production коде (удалите перед коммитом)
- Не полагайтесь только на Console.WriteLine (отладка — это профессионально)
- Не забывайте про Watch — это мощный инструмент
- Не игнорируйте Stack Trace — там часто ответ на ваш вопрос

## 12. ЧЕК-ЛИСТ ДЛЯ СОБЕСЕДОВАНИЯ 🎯

### Вопрос 1: Что такое отладка и зачем она нужна?

**Краткий ответ:** Отладка — процесс поиска и исправления ошибок в коде с помощью инструментов. Позволяет смотреть состояние переменных в конкретный момент и понимать, почему программа ведет себя неправильно.

### Вопрос 2: Какие основные инструменты отладки вы знаете?

**Краткий ответ:** Breakpoints (точки останова), Step Over/Into (пошаговое выполнение), Variables (инспекция переменных), Watch (отслеживание выражений), Stack Trace (стек вызовов).

### Вопрос 3: В чем разница между Step Over и Step Into?

**Краткий ответ:** Step Over (F10) — выполнить строку целиком, не заходя в методы. Step Into (F11) — зайти внутрь метода и смотреть пошагово, что там происходит.

### Вопрос 4: Когда использовать Conditional Breakpoint?

**Краткий ответ:** Когда нужно остановиться на конкретном условии — например, в 500-й итерации цикла вместо того, чтобы 500 раз нажимать F5.

### Вопрос 5: Как использовать Stack Trace при отладке?

**Краткий ответ:** Stack Trace показывает цепь вызовов методов, которые привели к текущей точке. Нажимайте на каждый уровень, чтобы смотреть значения переменных на каждом шаге.

### Вопрос 6: Когда использовать Logpoint вместо обычного Breakpoint?

**Краткий ответ:** Когда не хотите останавливать программу — Logpoint выводит сообщение в консоль. Полезно для отладки в фоне (например, отслеживание значений в цикле).

### Вопрос 7: Почему Watch считается мощным инструментом?

**Краткий ответ:** Watch позволяет отслеживать любое выражение (переменная, вычисление, вызов метода), смотреть, как оно меняется на каждом шаге, без необходимости добавлять консоль-логи.

### Вопрос 8: Как отладить тест, который падает?

**Краткий ответ:** 1) Поставьте breakpoint перед упавшей строкой. 2) Нажмите F5. 3) Смотрите Variables/Watch — какое значение неправильно? 4) Пошагово (F10/F11) выполняйте до места ошибки. 5) Нашли причину? Исправляйте.

### Вопрос 9: Практический пример: как отладить цикл, где в одной итерации ошибка?

**Краткий ответ:** Используйте Conditional Breakpoint с условием на индекс цикла (например, `i == 42`), чтобы остановиться в нужной итерации. Или используйте Logpoint для вывода значений всех итераций.

### Вопрос 10: В чем опасность оставить breakpoint в production коде?

**Краткий ответ:** Breakpoint замораживает программу при выполнении — в production это приведет к зависанию приложения. Всегда удаляйте breakpoints перед коммитом.
