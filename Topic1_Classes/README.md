# Topic1 — Классы и наследование (Подробная теория и примеры)

Цель: понять, что такое класс, как строить модели предметной области и применять ООП-принципы для написания чистого, поддерживаемого тестового кода.

Основные понятия
- Класс — шаблон (blueprint) для создания объектов. Содержит поля (данные) и методы (поведение).
- Объект — конкретный экземпляр класса.
- Конструктор — специальный метод, вызываемый при создании объекта; инициализирует состояние.
- Модификаторы доступа: `public`, `private`, `protected`, `internal` — контролируют видимость членов.
- Свойства (`get`/`set`) — обёртки над полями, позволяют контролировать доступ и валидацию.
- `readonly` и `init` — используются для создания неизменяемых/частично неизменяемых свойств.

Почему это важно для QA Automation
- Тестовые фреймворки и Page Object Model строятся вокруг классов.
- Правильная инкапсуляция помогает избегать хрупкости тестов и упрощает сопровождение.
- Понимание конструкторов и зависимостей облегчает чтение кода разработчиков и настройку фейковых/тестовых данных в консольных примерах.

Текстовые пояснения и советы
- Используйте приватные поля и публичные свойства для контроля доступа. Например, сделайте `private set` для свойства, которое не должно изменяться извне.
- Конструктор должен принимать обязательные зависимости и значения; опциональные параметры можно задавать через свойства.
- Для моделей данных, которые не должны изменяться после создания, используйте `readonly` поля или `init` свойства (C# 9+):
  - public string Name { get; init; }
- Инкапсуляция и валидация: внутри свойства `set` можно проверять входные значения и бросать `ArgumentException` при неверных данных.
- Разделяйте ответственность: класс должен отвечать за одну сущность/поведение. Это облегчает чтение и поддержку.

Примеры (ссылки на код в проекте)
- `Person.cs` — абстрактный базовый класс с защищёнными конструкторами и виртуальными методами.
  - Обратите внимание на перегрузку конструкторов и DRY-подход через вызов `: this(...)`.
- `User.cs` — конкретный класс-наследник, реализует абстрактный метод `GetSummary()`.
- `Employee.cs` — расширенный класс с приватными сеттерами и методами `SetPosition`, `SetSalary` для контроля изменения.
- `Program.cs` — практические сценарии создания объектов, использования именованных параметров и демонстрации полиморфизма.

Практические задания (консольные, без unit-тестов)
- Добавьте новый класс `Admin : User` с дополнительным свойством `CanManageUsers` и методом `GrantAccess(string user)` — продемонстрируйте его в `Program.cs`.
- В `Employee` реализуйте метод `CalculateTax()` который возвращает сумму налога от зарплаты (например, 13%) и вызовите его из консольного примера; добавьте валидацию параметров (например, зарплата не может быть отрицательной).
- Реализуйте property с `private set` и методами для контролируемого изменения состояния (например, `Promote()`), чтобы показать инкапсуляцию.

Рекомендации по написанию классов для автотестов
1. Используйте явные интерфейсы или базовые классы для Page Objects и сервисов — это упрощает подмену реализаций в примерах.
2. Держите поведение и данные в ясных границах: поля должны быть приватными, публичный доступ через свойства и методы.
3. Не делайте статические глобальные состояния там, где возможна инъекция зависимостей (чтобы примеры можно было изолировать).
4. Используйте конструктор для обязательных зависимостей, свойства для опциональных.
